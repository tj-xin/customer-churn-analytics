# 客户流失分析与预测

[English](README.md) | [简体中文](README_CN.md)

**一个结合探索性数据分析、机器学习建模、客户风险分层与留存策略模拟的端到端数据分析项目。**

本项目基于 Kaggle 2026 年 Playground Series S6E3 — Predict Customer Churn 竞赛数据，综合运用统计分析、机器学习与业务分析方法，探索客户流失的相关因素，建立客户流失预测模型，并进一步研究如何利用预测结果辅助客户留存资源分配。

**技术栈：** Python · Pandas · NumPy · SQL · Scikit-learn · LightGBM · Matplotlib · Seaborn · Git

## 2. 项目背景与业务目标

客户流失（Customer Churn）是订阅制企业面临的重要经营问题。

对于电信、互联网服务等行业，客户流失不仅意味着现有收入的减少，还可能增加企业重新获取客户的营销成本。

通过分析客户特征、服务订阅、合同类型和消费行为，可以识别具有较高流失风险的客户，为后续客户运营和留存策略提供参考。

本项目主要研究三个问题。

### 2.1 客户流失特征分析

哪些客户群体具有更高的流失率？

重点考察：

- 客户基本属性
- 在网时长
- 合同类型
- 服务订阅情况
- 支付方式
- 月费用和累计费用

通过分组统计、相关性分析和可视化，识别与客户流失相关的主要特征。

### 2.2 客户流失预测

能否利用客户已有信息预测其流失风险？

项目分别建立：

- Logistic Regression：可解释的统计基准模型
- LightGBM：能够捕捉非线性关系和特征交互的机器学习模型

通过统一的数据划分和评价指标，比较不同模型的预测表现。

### 2.3 客户留存决策支持

如果企业的营销资源有限，应该优先联系哪些客户？

项目利用预测概率对客户进行风险排序，并结合 Top-K 指标和假设性成本收益模型，分析不同客户联系比例下的潜在业务价值。

需要强调，**预测客户可能流失，不等于证明某项营销干预能够阻止其流失**。因此，业务收益部分采用明确假设下的模拟分析，而非真实营销效果评估。

## 4. 探索性数据分析（EDA）

通过描述统计、分组分析、相关性分析和可视化，探索不同客户群体的流失特征。

### 4.1 合同类型与客户流失

| 合同类型 | 实际流失率 |
|---|---:|
| 按月合同（Month-to-month） | 42.05% |
| 一年合同（One year） | 5.76% |
| 两年合同（Two year） | 1.00% |

按月合同客户的流失率明显高于长期合同客户。

考虑到合同类型与客户在网时长可能存在关联，项目进一步按照在网时长分组进行直接标准化分析。

| 合同类型 | 在网时长标准化后的流失率 |
|---|---:|
| 按月合同 | 35.15% |
| 一年合同 | 5.12% |
| 两年合同 | 0.67% |

标准化后，不同合同类型之间仍存在较大的流失率差异。

这说明合同类型与客户流失之间存在较强的统计关联，但不能据此断言将客户转为长期合同就一定能够降低流失风险。

### 4.2 在网时长与费用特征

其他主要发现包括：

- 在网时长 `tenure` 与累计费用 `TotalCharges` 呈较强正相关，Pearson 相关系数约为 0.7697。
- 不同月费用水平的客户具有不同的流失率。
- 互联网服务类型与客户费用特征、流失表现存在明显关联。
- 合同类型、在网时长、服务订阅和支付方式具有一定预测价值。

这些发现为后续多变量预测建模提供了分析依据。

**分析 Notebook：** [01_data_overview.ipynb](notebooks/01_data_overview.ipynb)

## 5. 机器学习建模

### 5.1 数据划分与验证策略

项目采用分层随机划分（Stratified Split），将带标签数据分为训练子集和验证子集。

| 配置项 | 设置 |
|---|---|
| 训练集比例 | 80% |
| 验证集比例 | 20% |
| 训练子集样本量 | 475,355 |
| 验证子集样本量 | 118,839 |
| 随机种子 | 42 |
| 核心评价指标 | ROC-AUC |

分层抽样用于保持训练集和验证集中流失客户的比例基本一致。

Kaggle 测试集不参与本地模型评价。

### 5.2 Logistic Regression 基准模型

逻辑回归具有较强的统计可解释性，适合作为二分类问题的基准模型。

使用逻辑回归的主要目的包括：

- 建立可解释的预测基准
- 衡量基础线性分类模型的表现
- 为 LightGBM 的性能提升提供比较依据

逻辑回归在验证集上的 ROC-AUC 为 **0.9084**。

**建模 Notebook：** [02_baseline_model.ipynb](notebooks/02_baseline_model.ipynb)

### 5.3 LightGBM 模型

LightGBM 是基于梯度提升决策树的机器学习算法，能够捕捉变量之间的非线性关系和交互作用。

本项目使用 LightGBM 原生类别特征处理方式。

主要超参数：

| 参数 | 设置 |
|---|---:|
| `n_estimators` | 300 |
| `learning_rate` | 0.05 |
| `num_leaves` | 31 |
| `random_state` | 42 |
| `n_jobs` | -1 |

项目优先保证验证策略合理、实验结果真实可复现，而不是进行大规模超参数搜索。

**建模 Notebook：** [03_lightgbm_model.ipynb](notebooks/03_lightgbm_model.ipynb)

## 6. 模型评价与实验结果

### 6.1 模型性能对比

| 评价指标 | Logistic Regression | LightGBM |
|---|---:|---:|
| 训练集 ROC-AUC | 0.9078 | 0.9183 |
| 验证集 ROC-AUC | 0.9084 | **0.9160** |
| PR-AUC（Average Precision） | 0.7271 | **0.7531** |

与 Logistic Regression 相比，LightGBM 的验证集 ROC-AUC 绝对提升约 **0.0076**。

LightGBM 的训练集与验证集 ROC-AUC 差距约为 0.0024，说明在当前验证方案下没有表现出明显的过拟合迹象。

但单次随机划分无法保证模型在未来时间段或不同客户群体中保持相同性能。

### 6.2 概率预测质量

LightGBM 在验证集上的 Brier Score 为：

**0.0954**

项目同时通过概率校准曲线分析模型预测概率与实际流失频率之间的一致程度。

对于客户风险管理，概率预测质量具有重要意义，因为业务决策往往依赖风险排序和概率水平，而不仅是二分类结果。

### 6.3 Kaggle 官方提交结果

完成本地验证后，使用全部 594,194 条带标签训练数据重新训练 LightGBM，并对 254,655 条 Kaggle 测试记录生成流失概率。

| 评价数据 | ROC-AUC |
|---|---:|
| 本地验证集 | 0.91600 |
| Kaggle Public | 0.91295 |
| Kaggle Private | **0.91415** |

**提交状态：** Complete (after deadline)。

本地验证集与 Kaggle 官方评测集不同，且最终提交模型使用全部训练数据重新拟合，因此不同成绩之间存在差异是正常现象。

这些成绩证明模型在相应竞赛评测数据上的预测表现，但不代表真实企业环境中的部署效果。

详细记录参见：[Kaggle 提交记录](kaggle/submission_history.md)。

## 7. 模型解释与特征重要性

项目采用 LightGBM 特征重要性和置换重要性（Permutation Importance）分析模型预测依据。

主要重要特征包括：

- `Contract`：合同类型
- `tenure`：在网时长
- `InternetService`：互联网服务类型
- `PaymentMethod`：支付方式
- `TotalCharges`：累计费用
- `MonthlyCharges`：月费用

其中，合同类型在模型中表现出较高的预测重要性。

项目同时比较了不同特征重要性方法的结果，认识到树模型的分裂次数、增益和置换重要性并不完全等价。

需要注意：

- 特征之间可能存在较强相关性。
- 不同重要性指标的解释角度不同。
- 预测重要性不等于因果效应。

因此，本项目将特征重要性作为解释模型预测行为的工具，而不将其直接解释为影响客户流失的因果机制。

## 8. 客户风险分层与业务分析

### 8.1 客户流失风险分层

根据 LightGBM 预测的流失概率，将验证集客户划分为五个规模近似相等的风险组。

| 风险等级 | 实际流失率 |
|---|---:|
| 极低风险（Very Low） | 0.21% |
| 低风险（Low） | 1.24% |
| 中风险（Medium） | 7.51% |
| 高风险（High） | 32.30% |
| 极高风险（Very High） | 71.35% |

结果显示，不同风险组之间存在明显的实际流失率差异。

这说明模型能够在当前验证数据中有效区分不同流失风险水平的客户。

### 8.2 Top-K 客户筛选

实际业务中，企业通常无法对所有客户开展留存营销，因此需要在有限预算下优先识别高风险客户。

项目采用 Top-K 指标衡量风险排序的业务价值。

| 联系客户比例 | 识别真实流失客户数 | Precision@K | Recall@K | Lift@K |
|---|---:|---:|---:|---:|
| Top 10% | 9,859 | 82.97% | 36.84% | 3.68 |
| Top 20% | 16,958 | 71.35% | 63.36% | 3.17 |
| Top 30% | 21,804 | 61.16% | 81.47% | 2.72 |

**核心发现：** 当只选择预测风险最高的 20% 客户时，可以识别出验证集中约 63.36% 的真实流失客户。

这表明预测模型具有一定的客户筛选和资源分配参考价值。

### 8.3 客户留存收益模拟

为了进一步研究模型预测结果的业务意义，项目构建了一个简化的客户留存成本收益模型。

假设期望净收益为：

\[
E[\mathrm{Profit}(K)]=TP@K\times q\times V-K\times C
\]

其中：

- \(TP@K\)：Top-K 客户中真实流失人数
- \(q\)：假设的营销干预成功率
- \(V\)：每成功留住一名客户的假设价值
- \(K\)：联系客户数量
- \(C\)：联系单个客户的假设成本

模拟参数：

| 参数 | 假设值 |
|---|---:|
| 单次客户联系成本 | 10 元 |
| 成功留存客户价值 | 200 元 |
| 干预成功率 | 10%、20%、30% |

不同营销预算下的模拟期望净收益：

| 联系比例 | 成功率 10% | 成功率 20% | 成功率 30% |
|---|---:|---:|---:|
| Top 10% | 78,350 元 | 275,530 元 | 472,710 元 |
| Top 20% | 101,490 元 | 440,650 元 | 779,810 元 |
| Top 30% | 79,570 元 | 515,650 元 | 951,730 元 |

在假设干预成功率为 20% 时：

LightGBM 相较 Logistic Regression，在相同的 Top 20% 联系预算下多识别 **332 名真实流失客户**，对应额外 **13,280 元模拟期望净收益**。

### 8.4 业务结论的适用边界

上述分析表明，客户流失预测模型可以为留存营销提供客户优先级排序依据。

但应注意：

**预测客户流失风险，不等于预测客户对营销干预的响应程度。**

真实业务中，营销效果还受到客户行为、干预方式、优惠力度及其他因素影响。

因此，本项目所有收益数据均属于**假设条件下的模拟结果**，不代表真实营销收入，也不构成营销措施有效性的因果证据。

## 11. 项目局限性

### 11.1 合成数据的外部有效性

本项目使用 Kaggle 合成数据，无法保证其统计分布、客户行为和业务规律与真实电信企业完全一致。

### 11.2 验证方案的局限

目前采用一次分层随机划分进行模型验证。

该方法可以评估模型在当前数据划分下的泛化表现，但无法充分检验模型的时间稳定性及跨业务场景的适用性。

### 11.3 相关性与因果关系

模型能够识别与客户流失相关的特征，但不能仅凭预测结果判断某项客户运营措施是否具有因果效果。

### 11.4 营销收益的假设性

业务模拟使用预先设定的联系成本、客户价值和干预成功率。

相关收益结果仅用于说明不同客户筛选策略在特定假设下的潜在差异。

### 11.5 未进行生产环境部署

本项目重点在于离线数据分析、模型训练、实验评价和业务解释，尚未构建生产级预测服务或模型监控系统。

## 12. 项目总结

本项目围绕客户流失预测问题，完成了从数据理解到业务分析的完整工作流程。

主要成果包括：

1. **数据分析：** 对 594,194 条带标签客户记录进行数据质量检查、分组分析和流失特征探索。
2. **机器学习：** 建立 Logistic Regression 基准模型与 LightGBM 模型，并进行统一评价。
3. **预测表现：** 获得 0.9160 的本地验证集 ROC-AUC 和 0.91415 的 Kaggle Private ROC-AUC。
4. **业务分析：** 在 Top 20% 高风险客户中识别出约 63.36% 的真实流失客户，并开展风险分层和假设性收益模拟。
5. **工程实践：** 使用 GitHub 管理代码、实验报告、数据字典、可复用模块与测试脚本。
6. **统计解释：** 明确区分预测能力、统计关联、因果关系和假设性业务收益。

项目的核心价值不仅在于建立具有一定预测性能的模型，更在于展示如何将统计分析、机器学习与业务决策问题连接起来，并在分析过程中保持可复现性和合理的解释边界。
